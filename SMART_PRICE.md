# SMART PRICE — Intelligent Food Price Monitoring System

## Запуск
Требуется Node.js 24. Проверено на Node 24.20.0. Встроенная SQLite не требует отдельной установки.

```powershell
npm ci
npm run test:smartprice
npm run build
npm start
```

Адрес: http://localhost:3005. На первом обращении сервер создаёт `data/smartprice.sqlite` и 8 960 тестовых наблюдений за 28 дней: 16 упаковок, 15 групп продуктов, 20 регионов/городов. Повторный запуск сохраняет данные. Не запускайте несколько инстансов с разными локальными дисками.

Выберите одну из трёх демо-ролей. Вход намеренно открыт для презентации; это не production-аутентификация. Сервер хранит хеши сессионных токенов, ставит HttpOnly/SameSite cookie и проверяет роль каждого изменения. Переключение ролей создаёт настоящую серверную сессию.

## Что работает
- Dashboard из SQLite, график корзины, рост/снижение, список сигналов.
- Каталог с отдельными SKU для 900 мл и 1 л; расчёт цены за кг, л, штуку.
- CRUD торговых точек и товаров. Справочники с историей защищены от удаления; параметры товара с ценами защищены от ретроактивного изменения. Точку можно отключить от мониторинга.
- Ввод и редактирование неподтверждённых собственных наблюдений, поиск, фильтры, история цены.
- Импорт CSV/XLSX до 1 000 строк, проверка дублей и значений, атомарный откат при ошибке.
- Объяснимые статистические сигналы, ручная проверка, комментарии, эскалация, заключения и журнал.
- Фото JPEG/PNG/WebP до 5 МБ: сигнатура файла проверяется, файл сохраняется в SQLite, доступ требует сессии. Автор, время, товар и магазин связаны с наблюдением.
- Кандидаты сопоставления по группе, названию, бренду, производителю, жирности и упаковке; подтверждение аналитиком. Разные размеры остаются разными SKU.
- Leaflet, реальная граница Казахстана, выбор регионов и реальные координаты центров городов. Тестовые магазины не имеют выдуманных адресов/GPS. После ввода координат магазин появится маркером.
- Excel с выбранными фильтрами. PDF через кнопку «Печать / сохранить PDF» и стандартное сохранение браузера. Печатная форма содержит все текущие наблюдения, а не только экранную страницу.
- Русский, қазақша, English; язык сохраняется в браузере.
- Четырёхшаговый интерактивный demo-flow через реальные API.
- Дополнительный CRM/ERP интерфейс сохранён по `/erp`.

## Аналитика и ограничения
Сигнал: изменение от предыдущего наблюдения не менее 15% в любую сторону либо цена выше медианы минимум трёх других магазинов на 30%. Это объяснимый baseline. Дополнительно обучена экспериментальная логистическая регрессия; её вероятность показана в паспорте цены. Итоговое решение принимает аналитик. Отклонённые наблюдения исключаются из текущего среза.

Корзина: сумма средних нормализованных цен по 15 семействам, по одной базовой единице каждого семейства. Это демонстрационная сравнительная корзина, не официальная норма потребления. Исторический график переносит последние известные наблюдения вперёд. Неполная корзина не получает выдуманного значения. Разные физические единицы нельзя ранжировать как взаимозаменяемые товары.

Реализованы OCR (Tesseract.js rus/kaz/eng), ручное подтверждение, полевые наблюдения, паспорт цены и отдельный вход сотрудников. Официальный срез БНС на 11.11.2026 содержит 651 агрегат по 31 категории и доступен отдельно от цен магазинов. Полевая база изначально пуста: реальные фотографии магазинов не предоставлены. SSO и непрерывный автоматический сбор не подключены. Основной интерфейс RU/KK/EN; новые исследовательские инструменты пока на русском.

Текущий MVP использует один Node.js сервер и постоянный локальный диск. Для промышленного размещения: PostgreSQL/Supabase вместо SQLite, объектное хранилище фото, резервные копии, ограничения запросов и пагинация API. `SMARTPRICE_DEMO_LOGIN=false` отключает открытый демо-вход; вход сотрудников по email/паролю остаётся доступным.

## API
Все GET/POST, кроме входа, требуют серверную сессию.

| Маршрут `/api/smartprice/…` | Метод | Назначение |
|---|---|---|
| login | POST | `{user_id: monitor / analyst / manager}` — открытый демо-вход |
| logout | POST | Отзыв сессии |
| data | GET | Срез товаров, точек, истории цен, сигналов и журнала |
| prices | POST | product_id, store_id, amount, collected_at ISO, source |
| price-edit | POST | id, amount; собственная неподтверждённая запись |
| products / stores | POST | Создание, изменение по id, удаление с delete:true |
| import-file | POST | multipart file .csv/.xlsx |
| import | POST | `{rows:[…]}` — атомарная пакетная загрузка |
| review | POST | id, status verified/rejected/pending, comment; аналитик |
| comment | POST | id, comment, escalate; специалист/аналитик |
| evidence | POST | id наблюдения, mime, base64, comment; специалист |
| evidence/{id} | GET | Фото |
| detail/{id} | GET | Комментарии и метаданные доказательств |
| match | POST | id, status confirmed/rejected; аналитик |
| export | GET | XLSX; region, product, store, from, to, lang |

Шаблон импорта:
```csv
product_id,store_id,amount,collected_at,source
oil,store-0,1100,2026-11-13T10:00:00.000Z,manual
```
Не импортируйте строку с датой позже текущего времени. Для просмотра ID продуктов используйте диалог импорта или API data.

## Новые инструменты для хакатона
Откройте верхний блок «Новые инструменты».

- Фото ценника: локальное OCR без внешнего API. Исходный текст и уверенность сохраняются отдельно от подтверждённой суммы. Товар, фасовку и цену проверяет сотрудник. Фото до 5 МБ.
- Полевая цена: отдельный аккаунт monitor, реальная точка, описание источника, время и явное подтверждение. Сохраняется в статусе pending. Фото загружается отдельным запросом; при ошибке интерфейс сообщает о необходимости повторной загрузки. Демо-аккаунты не могут изменять полевые записи через API.
- Корзина: одинаковые точные SKU и количества базовых единиц; только verified; ограничение возраста цены 1–90 дней. При пропусках/устаревании итог отсутствует. Упаковки не округляются до целых при расчёте стоимости заданного количества.
- Паспорт: оригинальный OCR, подтверждённая/текущая сумма, источник, фото, SHA-256, версия и вероятность модели, сопоставление, журнал решений, JSON-экспорт. SHA-256 не доказывает истинность источника.
- Модель: npm run train:smartprice. 3200 train / 800 validation / 1200 test, независимые синтетические группы. F1 0.9606, baseline 0.9360. Не оценка качества на реальном рынке. Артефакт фиксирует seed, веса, порог, confusion matrix и хеш набора.
- OCR benchmark: node scripts/smartprice/evaluate-ocr.cjs. 12 синтетических ценников, 12/12 точных сумм после обработки пробелов. Это проверочный набор разработки, не независимая оценка на фотографиях магазинов.
- БНС: node scripts/smartprice/import-bns.cjs. Публичный официальный Excel, исходник/хеш/даты сохранены в public/smartprice/sources. Данные — средние по городам, не SKU и не магазинные наблюдения. Импорт запускается явно, расписания нет.

### Отдельные аккаунты
Установите переменную SMARTPRICE_ACCOUNT_PASSWORD (минимум 12 символов) и выполните npm run account:smartprice -- email@example.kz monitor "Имя сотрудника". Аналогично выдаются роли analyst и manager. Затем удалите переменную из окружения. Пароль не передавайте аргументом команды и не публикуйте в репозитории. Саморегистрации с выбором роли нет. Используются scrypt, случайная соль, хеш сессионного токена, HttpOnly cookie и блокировка входа после пяти ошибок на 15 минут.

### Новые API
POST account-login {email,password}; POST field-store; POST field-price {product_id,store_id,amount,collected_at,source_url,ocr_text,ocr_confidence,confirmed:true}; POST basket {dataset:demo|field,max_age_days,items:[{product_id,quantity}]}; GET passport/:id; GET model. Экспорт принимает dataset=demo|field. Healthcheck: /api/health.

### Постоянная публикация
Включён render.yaml для Docker-сервиса с постоянным диском. Это конфигурация платного размещения; сервис не создан и оплата не подключена. Демо-вход отключён в конфигурации. После размещения через консоль хостинга создайте отдельные аккаунты командой выше. SQLite требует единственного экземпляра сервера и постоянного диска; перед несколькими экземплярами перенесите базу в PostgreSQL. До работы с реальными персональными данными требуется обновление унаследованной версии Next.js и проверка зависимостей (npm audit), резервное копирование и контроль доступа.
